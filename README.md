## 1. サービス概要

**製造業における品質管理データをSPC管理図として可視化し、工程のトレンドを共有するためのサポートツール**  
CSVデータを読み込ませるだけで`異常値の計算`,`データの可視化`が可能なアプリ。  
`データの可視化`という点においては［複数（カラム）データの全体像］から［個別（カラム）データの確認/比較］までの解析者に伝わりやすい構成でグラフ切り替えが可能。
また、解析アクションをフロントエンドでのみに絞ることでサーバー通信による`データ流出の懸念をなくしている`。
>>SPC管理（統計的工程管理：Statistical Process Control）とは、==製造業において、製品の品質データや設備の稼働状況を統計的に分析・監視し、異常を早期に検知して不良品の発生を未然に防ぐ品質管理手法==です。

#### ■ 解決したい課題のスコープ（何ができるか / 境界線の明示）

本サービスは、「セキュリティリスクゼロでの、データの可視化から情報の即時把握」までを最速化することを絶対的なスコープとしています。
```プラットフォームにおけるデータ取扱いルールの実装ガイダンス
データ利活用による価値創出プロセス

1. 生成・収集・蓄積
    - 観測や測定によってデータを取得し、蓄積するフェーズ。
2. 統合・加工：≪本アプリの機能提供範囲≫
    - 収集したデータのアノテーションを付与したりするフェーズ。
3. 分析
    - 知見・情報を導き出すフェーズ。
4. 価値創出・価値享受
    - 分析結果から課題解決を行い、エンドユーザーへ価値を提供する
```

- **【スコープ内】**：ブラウザ内でのCSV読込、統計計算（平均値、標準偏差、管理限界線の算出）、議論構成を想定したグラフ切り替え、管理図の動的描画、ホバー（ツールチップ）による異常・変化傾向の視覚的ハイライト、および画面を閉じた際のデータ即時破棄。
- **【スコープ外】**：異常原因の特定や具体的な改善対策の自動提示、およびデータの永続化（保存機能）。これらは、可視化された情報をもとに「現場の人間」が議論して決定する領域と位置づけています。

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

＜きっかけとなった感情＞
- **形骸化した議論：** 蓄積したデータを報告用レポートにまとめる品質管理業務に従事する際、大量の数値を並べただけのExcelの表シートを前に、特定の外れ値だけに注目が集まり、工程全体の安定性や予兆といった「真に議論すべき統計的事実」が埋もれてしまう状況に危機感を感じていました。

＜きっかけとなった体験＞
- **変化への気づき：** 製造部門から研究開発部門へ異動した際、**データの見せ方** 一つでチームの意思決定スピードと精度が劇的に変わることを実感し、**「グラフという共通言語」の重要性**を痛感しました。
---
### 2-2. なぜそれが「気になった」のか

専門知識や経験を持つ一部の人にしか現状を正しく理解できなかった情報をチーム全体の「方向性」を一致させることが困難だったからです。

本アプリのアイデアは単にデータ前処理工程を効率化するだけでなく、**「グラフを駆使して議論することの素晴らしさ」** をアプリを通して共有したいと考えています。データが「報告のための重荷」から「チームの総意を形作るための強力なツール」へと変わる体験を、かつての自分と同じように現場で奮闘する仲間に届けたいという思いから、このアプリの制作を決意しました。

## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

正しく扱われていないデータからは効率のいい情報と判断が難しい。

### 3-2. 本当に解決したい課題は何か

1. **なぜ数値の羅列だと議論に時間がかかるのか？（1回目）** 数値だけでは「工程が安定しているのか」「異常の予兆があるのか」といった統計的な事実が直感的に理解できず、参加者の経験値や勘によって解釈が分かれてしまうから。
2. **なぜグラフ（SPC管理図）を用いた議論が浸透しないのか？（2回目）** 管理図の作成には、複数のExcelファイルからのデータ集計や煩雑な書式設定が必要で、多忙な現場では「議論の準備」にリソースを使い果たしてしまうから。また、長年の「数値のみで議論する慣習」により、可視化がもたらす議論の質の高さを体験する機会が奪われているから。
3. **なぜ、議論の質の高さを体験する機会が奪われることが問題なのか？（3回目）** 
   本来最も時間を割くべき「チーム総意としての方向性」という建設的な対話が不足するから。  

    **➡ 本当に解決したい課題** 　
    **「データを正しく認識するすべを理解し、チームの意思決定に貢献する」**

## 5. 既存サービス・競合調査

### 5-1. 似たサービスの調査

### サービス概要

- **サービス名**：xGrapher（エックスグラファー）  
    
- **URL**：[https://xgrapher.com/charts/control](https://xgrapher.com/charts/control)  
    
- **どんなことができるか**： ブラウザ上でデータを入力または一括貼り付けするだけで、品質管理に必要な**中心線（CL）や管理限界線（UCL / LCL）(3σ)を自動計算し、マーカー付きの管理図（折れ線グラフ）を瞬時に作成・画像ダウンロードできる**オンラインツールです。  
    

### このツールの「良い点」（メリット）

特に実務やシステム開発の検証において優れていると感じる点は以下の通りです。

#### 1. エクセルでの「面倒な限界線計算」が一切不要（★最大のご利益）

通常、Excelで管理図を作る場合、平均値（AVERAGE）や最大・最小の差（MAX-MIN）、さらにサンプル数に応じた管理図用係数（A2など）を調べて数式を組む必要があります。 xGrapherは**データを貼り付けるだけで、3σ基準のUCL/LCL（上方・下方管理限界線）を自動で計算して描画してくれる**ため、計算ミスが起きず、一瞬で正しい管理図が得られます。

#### 2. 完全無料・アカウント登録不要で即座に使える

ログインや会員登録の手間が一切なく、サイトを開いた瞬間にデータを入力してグラフ化できます。社外ツールのアカウント作成が厳しい環境や、「ちょっとこのデータセットの傾向をパッと見たい」という時に非常にフットワークが軽いです。

#### 3. CSVデータなどからの「一括入力」に対応している

画面内に「一括入力」のタブが用意されており、タブ区切りやカンマ区切りのテキストデータをコピー＆ペーストするだけで、大量のプロットデータを一気にグラフに反映させることができます。

#### 4. 作成した管理図を画像として保存できる

出来上がった管理図は、設定やスタイルをカスタマイズした上で画像としてダウンロード可能です。報告書（デイリーレポート等）への添付や、プレゼン資料への貼り付けがスムーズに行えます。

## 8. このアプリの懸念点とその対策

### 懸念点①：機密データの外部アップロードに関するリスク

- **懸念点**: 製造現場のリアルな生産・品質データ（SPC管理図用の数値など）には企業の機密情報が含まれるため、個人開発の外部サーバーにデータをアップロード・保存することに対して、組織のセキュリティ規程上、非常に高いハードルがあります。このリスクを完全にゼロにしなければ、現場で実際に使われるアプリにはなり得ないという懸念があります。
- **ブラウザ内（ローカルメモリ上）での処理完結**: データのアップロード・保存を行うサーバーサイドの通信を一切行わず、「ユーザーのブラウザ（JavaScript）だけでCSVのパース、統計計算、グラフ描画までをすべて完結させる」アーキテクチャへと設計を変更します。データがインターネットを介して外部サーバーへ送信されないため、情報漏洩リスクを構造上、なくします。

### 10-2. 【重要】データベース（MySQL）の役割とデータ取扱いの境界線
本アプリのコアコンセプトである「セキュリティリスクゼロ（外部へのデータ流出防止）」を確実に担保するため、DBへ保存するデータと、ブラウザ上（ローカルメモリ）でのみ処理するデータを厳格に分離して設計します。

| データの種類                       | 保存先                   | 理由・取扱い                                                                                                 |     |
| ---------------------------- | --------------------- | ------------------------------------------------------------------------------------------------------ | --- |
| **CSVの測定データ（数値）**            | **一切保存しない** (ローカルメモリ) | サーバー通信を行わず、ユーザーのブラウザ内（JavaScript）だけで使い捨てるため、DBには1バイトも保存・送信しません。                                        |     |
| **ユーザーのアカウント情報**             | **MySQL (DB)**        | ログイン認証機能（マイページへのアクセス）のためにのみ使用します。                                                                      |     |
| ＜MVP実装なし＞<br>**グラフの表示・判定設定** | **MySQL (DB)**        | 「どのCSVカラムをグラフに描画するか」「TEST1〜3のどのルールを適用するか」といった**設定プロファイル（メタデータ）のみ**を保存し、次回ログイン時に同じ設定で即座に解析を始められるようにします。 |     |

本アプリのコア機能を実現するにあたり、現時点で学習・実装経験が不足している技術要素について、以下の懸念点と具体的な解決アプローチを定義し、開発の停滞リスクを最小限に抑えます。  
① フロントエンド処理の連携

- **懸念点**: フロントエンド（ブラウザ上）で大規模なデータ（数百〜数千件）をループ処理しながらSPCの判定（TEST1、TEST2等）を行う際、UIのフリーズ（メインスレッドの占有）が発生するリスクや、複雑な統計計算ロジック（`simple-statistics` を用いた配列操作）の実装不備により、計算結果のバグや描画遅延が発生する懸念があります。
- **対策と検証アプローチ**:
    - **ミニアプリによる早期検証**: 本開発に入る前に、数千行のサンプルCSVを読み込んで「平均・標準偏差・UCL・LCL」の数値を正しく算出・出力するだけの単機能なスクリプトをローカル環境で作成し、計算精度と処理速度の検証を行います。.
