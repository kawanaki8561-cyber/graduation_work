## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

蓄積したデータを報告用レポートにまとめる品質管理業務に従事する際、以下の点に不便性・不満を感じていた。

- 複数のファイルにアクセスし、手作業でデータをコピー＆ペーストする繰り返し作業。
- 苦労して取得したデータを数値羅列のみでの解析作業。
- レポートのまとめ方もエクセル上に数値データを記載し、その上から吹き出し図でコメントする形式で非常に全体像を掴みづらく且つ、相手に伝わりづらい。
- 並行して進行するライン業務があるため、上記業務に力を注ぐことが出来ない。

---

### 2-2. なぜそれが「気になった」のか

私は複数の並行作業を掛け持つことが苦手なため、メイン業務（ライン作業）にタスク配分のリソースをほとんど振ってしまうことが多かった。そのため、データ解析結果を報告する場では現状を正確に共有することが難しくなっていました。  
また、当時の個人的な感情として伝える・議論するということの重要性に感じていなかったことも原因にあります。  
しかし、自分が製造部門から研究開発部門に異動したことをきっかけに議論の重要性を以下の点で考えるようになりました。
- グループの行動方針を決める重要なピースとなること
- 現状把握と目標値を明確にすることができる
- 新たな意見を取り入れることができる

### 3-2. 本当に解決したい課題は何か

**表に見えている困りごと：** 相手に自分の伝えていたいことが伝わらない

1. **なぜ伝わらないのか？（1回目）** データが数値の羅列のみで視覚的な傾向が掴みづらく、Excel上の吹き出しコメントも煩雑なため、情報の「全体像」や「異常」を一目で把握することが困難だから。
2. **なぜ一目で把握できる形式（視覚化）にできないのか？（2回目）** 資料作成のみがメイン業務ではないため、時間のリソースを状況把握と異常解析（現場を回すために最低限必要な判断）に割くことしかできないから。
3. **なぜ「資料作成（視覚化）」にリソースを割けないことが問題なのか？（3回目）** 自身の状況把握にも時間が掛かる上、相手の情報読み取り難度も上がってしまう。その結果、限られた時間の中で正確な情報を取得し、異常対策などの今後の方向性をスムーズに決める（意思決定する）ことが難しくなっているから。

#### ➡ 本当に解決したい課題

**報告のための資料作成という「作業負担」を極限まで減らし、現場の担当者とチームが、最短ルートで正確な現状把握を行い、「次のアクションに向けた建設的な議論と意思決定」に専念できる環境を作ること。**

### 4-3. 実際に使われる可能性について(需要・存在確認)

1. データ移行のハードルについての深掘り

- 「**機密性の低い統計データ（数値のみのCSV）に加工した上でアップロードする**」
- 「機密データは上げられない」という現場のハードルに対し、メタデータ（カラム名）を除く数値の蓄積データならば使えるという妥当性を示す

2. 長期利用のメリット：トレンド把握と未来予測

- 年月をまたいだデータの蓄積により、季節変動や設備の経年劣化の予兆（トレンド）を自動で検知できる

3. 「自分でも使いたい」と思える決め手

- 「**複数のExcelからコピペする作業が、1回のドラッグ＆ドロップで終わること**」
- 「**数値の羅列が1秒で管理図（グラフ）になり、異常箇所が強調されること**」
